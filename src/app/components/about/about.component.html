The problem

The job is simple. The tooling often is not.

Exporting a database should not require a pile of one-off commands, format decisions, and file shuffling. The job is easy to describe: connect, collect the documents, and leave with an archive.

{{ brand.name }} aims at that gap. Paste a connection URI, let the server write each collection as JSON, and download one ZIP. That server step is still to be built. This page only explains the intent.

Vision

Make database backups straightforward for developers.

A short path from a connection string to an archive of ordinary JSON. Readable documents, one download, and no extra ceremony around a task that should already feel routine.

Principles

How the product should behave.

Simplicity

One path from a connection string to an archive. The interface should not grow a second product around the backup.

Transparency

The export format is meant to be JSON you can open and inspect, including Extended JSON for BSON values.

Security-conscious engineering

Credentials, storage, and limits will be handled deliberately in the backend. The interface will not claim controls that are not in place.

Developer experience

A workflow that fits how developers already work: a URI, a file you can unzip, and documents you can read.
